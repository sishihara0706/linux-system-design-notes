# IPC（プロセス間通信）

別プロセスに分けた処理は、何らかの方法で情報を交換する必要があります。これがIPC（Inter-Process Communication）です。

## 主なIPC

| 手段 | 向いている用途 |
|---|---|
| pipe | 親子プロセス間の単純なストリーム |
| Unix domain socket | 双方向通信、メッセージ交換 |
| socketpair | 関係の深い2プロセス間の双方向通信 |
| shared memory / mmap | 大容量データの高速共有 |
| semaphore / mutex | 共有資源の同期 |
| eventfd | 軽量なイベント通知 |

## 制御情報と大容量データを分ける

典型的には次のように役割を分けられます。

```text
Control message -> Unix socket / pipe
Large data      -> shared memory
Notification    -> eventfd
```

例えば大きな画像バッファを毎回socketへコピーするより、データ本体は共有メモリに置き、「新しいデータがある」という通知だけを軽量なIPCで送る方法があります。

## IPC設計で考えること

- 通信方向は片方向か双方向か
- メッセージ境界が必要か
- データ量はどの程度か
- コピーコストは許容できるか
- 相手プロセスが落ちたことをどう検出するか
- タイムアウトをどう扱うか
- バージョン違いのプロセス間でプロトコルをどう保つか

IPCは単なる通信手段ではなく、プロセス間の契約でもあります。
