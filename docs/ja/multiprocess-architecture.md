# マルチプロセスアーキテクチャ

## なぜ複数プロセスに分けるのか

マルチプロセス設計では、役割ごとに処理を別プロセスへ分離します。

```text
GUI / Manager
   |
   +-- Worker A
   +-- Worker B
   `-- Worker C
```

主な目的は次のとおりです。

- 障害を局所化する
- CPU負荷の高い処理をUIから分離する
- 権限やリソースをプロセス単位で管理する
- 一部のWorkerだけを再起動できるようにする
- プロセスごとの責務を明確にする

## プロセス分離の利点

1つのWorkerがクラッシュしても、別プロセスで動くコンポーネントは必ずしも巻き込まれません。

```text
Worker B -> SIGSEGV

Worker A   alive
Worker B   dead
Worker C   alive
GUI        alive
```

ただし、プロセスを分ければ自動的に堅牢になるわけではありません。IPC、再起動、状態復旧、タイムアウト、ログなども合わせて設計する必要があります。

## 分けすぎにも注意

すべてを別プロセスにすると、IPCや状態管理が複雑になります。

特に大量データを頻繁に受け渡す処理では、単純なsocket通信だけではコピーコストが問題になる場合があります。その場合は共有メモリなどを検討します。

設計では「プロセスを分けられるか」ではなく、**障害境界・責務・データ量を考えたときに分ける価値があるか**を判断します。
